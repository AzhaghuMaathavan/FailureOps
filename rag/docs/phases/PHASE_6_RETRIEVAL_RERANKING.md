# Phase 6 Retrieval and Reranking

## 1. Files created/modified
- `app/core/config.py`: Added settings for `TOP_K` (15), `RERANK_TOP_K` (5), `SIMILARITY_THRESHOLD` (0.8), and configured the explicit `nvidia/rerank-qa-mistral-4b` model URL.
- `app/services/embedding_service.py`: Added the `embed_query` helper to fetch the 2048-dim vector for incoming user queries.
- `app/services/retrieval_service.py`: Built the core `search_knowledge_base` engine that manages vector search and candidate reranking without inserting Agent logic.
- `app/api/retrieval.py`: Created the internal developer testing endpoint `POST /api/v1/retrieval/search`.
- `test_retrieval.py`: Integration testing script proving retrieval performance across real data.

## 2. Architecture and pgvector Execution
The pipeline strictly follows the "Evidence Only" principle:
1. **Query Embedding**: The user string is submitted to `nemotron-3-embed-1b`.
2. **Vector Candidate Retrieval**: An explicit PostgreSQL `ORDER BY embedding <=> query_vector` limits results to `TOP_K`. It filters chunks by `embedding_status == 'COMPLETED'`.
3. **NVIDIA Reranking**: The `TOP_K` chunks are batched into a typed `{"query": {"text":...}, "passages": [{"text":...}]}` JSON payload for `nvidia/rerank-qa-mistral-4b`.
4. **Ranked Evidence Return**: The engine bounds the results to `RERANK_TOP_K`, preserving all metadata.

## 3. Score Handling and Lineage
No data is overwritten. Every returned piece of evidence perfectly preserves:
- **`vector_distance`**: The exact cosine distance calculated by Postgres.
- **`rerank_score`**: The logit output generated by the Mistral reranker.
- **`lineage`**: The exact `{page_ids, block_ids}` required for future agent citations.
- **`headers`**: The semantic hierarchy associated with the text/table.

## 4. Test Results and Efficacy
Testing confirmed that the retrieval mechanism works brilliantly, especially in establishing signals for the future Refusal Engine:

- **Factual Question ("Purpose of RAGFlow")**: 
  - Correct chunk retrieved with vector distance `0.44`. Reranker boosted it to a massive `+11.4` score.
- **Table Retrieval ("Subjects on Monday at 11 AM")**: 
  - The LaTeX table chunk was correctly retrieved (distance `0.55`) and heavily upranked (`+3.5`). The model seamlessly understood the tabular format.
- **Unrelated Question ("Airspeed velocity of a swallow")**: 
  - Vector cosine distance for the top result degraded to `~1.0` (orthogonal).
  - The Reranker punished all retrieved passages with severe negative scores (`-18.1`). 
  - *This perfectly sets up the future Agent to trigger a refusal based on quantitative thresholds.*

## 5. Known Limitations & Next Steps
- **Metadata Filters**: The engine accepts optional document IDs, but more complex generic filters (department, academic year) can be wired into the SQLAlchemy query later once Document metadata is fully modeled.
- **Agent Hand-off**: The current system only returns ranked JSON evidence. The next phase will build the Agentic layer to evaluate these scores and synthesize the final grounded response.
